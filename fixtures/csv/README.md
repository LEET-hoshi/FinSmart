# CSV-фикстуры для проверки импорта

Формат: `operation_id,date,amount,currency,description,mcc` (см. `docs/api/openapi.yaml`, `POST /transactions/import`). Ожидаемый результат при импорте каждого файла в пустую базу пользователя:

| Файл | imported | duplicates | failed | Что проверяет |
|---|---|---|---|---|
| `valid.csv` | 12 | 0 | 0 | Корректный файл: 11 расходов, 1 поступление (`abc-010`, без MCC → `other`), операция за прошлый месяц для сравнения. |
| `duplicates.csv` | 2 | 2 | 0 | Повтор `operation_id` внутри файла: вторая строка с тем же id пропускается и не меняет сохранённую операцию (`dup-002` остаётся с суммой -1200.00). Повторный импорт файла в ту же базу даёт `imported 0, duplicates 4`. |
| `invalid.csv` | 2 | 0 | 6 | Ошибочные строки не мешают сохранению корректных. Номера строк (заголовок — строка 1): 3 — `date`, 4 — `amount`, 5 — `amount` (ноль), 6 — `currency`, 7 — `mcc`, 8 — `operation_id`. |
| `unknown_mcc.csv` | 2 | 0 | 0 | Неизвестный и пустой MCC получают категорию `other`. |

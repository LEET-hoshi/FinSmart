# Состояние backend (T1)

Актуально на 31.10.2026, после объединения работы двух разработчиков в `main`.

## Что работает

Запуск: `docker compose up --build` (см. README). Сквозная проверка демо-сценария: `API=http://localhost:18080 bash scripts/smoke.sh` — 28 проверок, на момент слияния все зелёные. Юнит-тесты: `cd server && ./gradlew test` (JDK 21) — 21 тест.

| Область | Эндпоинты | Где в коде |
|---|---|---|
| Служебное | `GET /health`, `GET /categories` | `health/`, `categories/` |
| Auth | `POST /auth/register`, `/login`, `/refresh`, `/logout` | `auth/` — BCrypt, JWT (access 1 ч, refresh 30 дней без ротации), в БД только SHA-256 хеш refresh-токена |
| Импорт | `POST /transactions/import` | `transactions/` — разбор в `CsvImportParser`, вставка `ON CONFLICT DO NOTHING`, частичный успех |
| Операции | `GET /transactions`, `PATCH /transactions/{id}/category` | `transactions/` — ручная категория не перезаписывается повторным импортом |
| Аналитика | `GET /analytics/summary?month=` | `analytics/` — только расходы, по модулю |
| Цели | `GET/POST/PATCH /goals` | `goals/` — типы `saving` и `spending_limit`; у лимита потраченное считается из транзакций за текущий месяц |
| Скидки | `GET /offers`, `GET /offers/{id}` | `offers/` — каталог грузится при старте из `OFFERS_FILE` |

Данные пользователей изолированы: `userId` берётся только из JWT, чужие объекты дают 404.

## Как объединяли (чтобы не гадать, откуда что)

Основа — послойный код разработчика backend (`auth/`, `transactions/`, `analytics/`, `categories/`, `common/`: Repository → Service → Routes). Поверх него добавлено:

- **Парсер CSV** — `transactions/CsvImportParser` вместо `CsvParser` (по просьбе разработчика): 15 тестов. Из прежнего парсера перенесены защиты: строгий UTF-8, не более 12 цифр суммы до точки (иначе переполнение `NUMERIC(14,2)`), описание до 500 символов.
- **`operation_id`** — любая непустая строка до 64 символов, не обязательно UUID (пример из ТЗ — `abc-001`, контракт `docs/api/openapi.yaml`). Фикстура `fixtures/csv/invalid.csv` поправлена: строка 3 теперь с `operation_id` длиннее 64 символов.
- **Миграции:** V1 (схема), V2 (`refresh_tokens`, версия из `main`), V3 (тип цели, `deleted_at`, `sync_changes`), повторяемый seed категорий и MCC.
- **Цели и скидки** написаны отдельно; `common/Support.kt` — тонкий слой совместимости (валидация, деньги строкой, `Connection.requireCategory`).
- Все выборки по транзакциям учитывают `deleted_at IS NULL`.

## Нужно согласовать (влияет на контракт)

- **Тип цели в OpenAPI.** В `docs/api/openapi.yaml` у `Goal` нет `type`; backend уже принимает и отдаёт `saving | spending_limit`, для лимита `currentAmount` — потрачено за месяц (считает сервер).
- **Категория предложения.** В БД `offer_categories` многие-ко-многим, в API одна `category` — сейчас отдаётся первая по коду.
- **`isTest`** есть в фикстуре и БД, в API-схему `Offer` не включён.
- **Сортировка `/offers`** контракт не задаёт; реализовано «по выгоде».
- **ТЗ vs контракт.** Главным выбран контракт (строки для денег, `month`, snake_case-коды, `errors`/`category`, `open_offers`). ТЗ в этих местах устарело.

## Запуск: подводные камни

- Порт 8080 может быть занят (у нас там Apache): задайте `API_PORT` в `.env`.
- `JWT_SECRET` (32+ символа) обязателен; значение по умолчанию в `docker-compose.yml` — только для разработки.
- Каталог скидок монтируется из `./fixtures` (переменная `FIXTURES_DIR`). Пустой, битый или отсутствующий файл каталог не затирает — проверено на стенде: после пустого `offers.json` остались прежние акции.

## Известные ограничения

- Возвраты (положительные суммы) расходы не уменьшают — только `amount < 0`.
- CSV с переносами строк внутри кавычек не поддерживается.
- Нет защиты от перебора паролей и ограничения частоты запросов.

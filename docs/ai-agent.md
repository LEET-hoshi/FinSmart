# Контракт ИИ-рекомендации

`GET /ai/recommendation?month=YYYY-MM` возвращает одну рекомендацию по схеме `Recommendation` из OpenAPI.
Поле `category` содержит системный код. Клиент при `actionType: open_offers` передаёт его в
`GET /offers?category=...`; человекочитаемое русское имя находится в `message`.

## Правила и данные

Rule-based fallback выбирает категорию с наибольшим положительным ростом суммы расходов среди категорий за запрошенный
месяц, а не `topCategory` (которая означает только наибольшую текущую сумму). При наличии такой категории возвращается
`open_offers`. Если прошлого периода нет, рекомендация нейтральна. В агрегат также передаётся процент ближайшей к
завершению активной цели (`goalProgressPercent`); он может быть упомянут в сообщении, но не меняет финансовые расчёты.

Разрешённый внешний вход для LLM — только агрегат: суммы двух периодов, процент изменения, коды категорий и прогресс
цели. CSV-файлы, описания операций, email, идентификаторы пользователя или операций, JWT и другие персональные данные
не попадают в payload.

## LLM feature flag

По умолчанию LLM выключена. Для включения требуются `LLM_ENABLED=true`, `LLM_ENDPOINT` и при необходимости
`LLM_API_KEY`; `LLM_TIMEOUT_SECONDS` ограничен диапазоном 1–30 секунд (по умолчанию 5). Endpoint должен принять
разрешённый агрегат и вернуть ровно такой JSON без дополнительных полей:

```json
{
  "title": "Короткий заголовок",
  "message": "Проверьте скидки в категории «Дом».",
  "category": "home",
  "actionType": "open_offers",
  "actionLabel": "Посмотреть скидки"
}
```

Сервер проверяет точный набор полей, длины строк, тип действия и код категории. При заполненной `category` поле
`message` должно содержать русское название из справочника, например «Дом» для `home`. Для `open_offers` категория
обязательна, а для `none` `actionLabel` должен быть `null`. Таймаут охватывает получение заголовков и тела ответа.
При таймауте, сетевой ошибке, неуспешном HTTP-статусе или невалидном ответе API возвращает HTTP 200
с рекомендацией `source: rules`. Валидный внешний ответ возвращается с `source: llm`.

## Демонстрационные примеры

Оба примера используют синтетические операции из [`recommendation-demo.csv`](../fixtures/csv/recommendation-demo.csv).
В октябре продукты составили 1 000 ₽ при росте на 100 ₽, дом — 500 ₽ при росте на 300 ₽, кафе — 200 ₽ при росте на 150 ₽.

### Rules

При отключённой LLM вызов `GET /ai/recommendation?month=2026-10` возвращает:

```json
{
  "title": "Расходы выросли",
  "message": "Расходы в категории «Дом» выросли сильнее всего. Посмотрите скидки в этой категории.",
  "category": "home",
  "actionType": "open_offers",
  "actionLabel": "Посмотреть скидки",
  "source": "rules"
}
```

### LLM

Для демонстрации используется заглушка на `127.0.0.1` без ключа провайдера. В этом сценарии также есть синтетическая цель
с прогрессом 50%. Тело запроса FinSmart к заглушке:

```json
{
  "totalExpense": "1700.00",
  "previousTotalExpense": "1150.00",
  "changePercent": 47.8,
  "goalProgressPercent": 50.0,
  "categories": "groceries,home,cafes"
}
```

Публичный ответ FinSmart после успешного ответа заглушки:

```json
{
  "title": "Проверьте скидки",
  "message": "Сравните предложения для категории «Дом» перед следующей покупкой.",
  "category": "home",
  "actionType": "open_offers",
  "actionLabel": "Посмотреть скидки",
  "source": "llm"
}
```

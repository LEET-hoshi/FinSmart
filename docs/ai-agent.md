# Контракт ИИ-рекомендации

`GET /ai/recommendation?month=YYYY-MM` всегда возвращает одну рекомендацию по схеме `Recommendation` из OpenAPI.
Поле `category` — один из системных кодов, а не текст для показа. Клиент при `actionType: open_offers` передаёт его в
`GET /offers?category=...`; человекочитаемое русское имя находится в `message`.

## Правила и данные

Rule-based fallback выбирает категорию с наибольшим положительным ростом суммы расходов среди категорий за запрошенный
месяц, а не `topCategory` (которая означает только наибольшую текущую сумму). При наличии такой категории возвращается
`open_offers`. Если прошлого периода нет, рекомендация нейтральна. В агрегат также передаётся процент ближайшей к
завершению активной цели (`goalProgressPercent`); он может быть упомянут в сообщении, но не меняет финансовые расчёты.

Разрешённый внешний вход для LLM — только агрегат: суммы двух периодов, процент изменения, коды категорий и прогресс
цели. CSV-файлы, описания операций, email, идентификаторы пользователя или операций, JWT и другие персональные данные
не попадают в payload.

## LLM feature flag

По умолчанию LLM выключена. Для включения требуются `LLM_ENABLED=true`, `LLM_ENDPOINT` и при необходимости
`LLM_API_KEY`; `LLM_TIMEOUT_SECONDS` ограничен диапазоном 1–30 секунд (по умолчанию 5). Endpoint должен принять
разрешённый агрегат и вернуть ровно такой JSON без дополнительных полей:

```json
{
  "title": "Короткий заголовок",
  "message": "Понятный совет",
  "category": "home",
  "actionType": "open_offers",
  "actionLabel": "Посмотреть скидки"
}
```

Сервер строго проверяет поля, длины, тип действия и код категории. Для `open_offers` категория обязательна, а для
`none` `actionLabel` должен быть `null`. Таймаут, сетевая ошибка, неуспешный HTTP-ответ или невалидный JSON не выходят
наружу: сервер возвращает rule-based ответ с `source: rules`. Валидный внешний ответ сохраняет `source: llm`.

# 0001. Решения по API-контракту MVP

Дата: 29.10.2026. Контракт: `docs/api/openapi.yaml`.

## Авторизация

- Access-токен (JWT) живёт 1 час, refresh-токен — 30 дней.
- `POST /auth/refresh` выдаёт новый access-токен; refresh-токен при этом не меняется (без ротации — она перенесена после дедлайна).
- Refresh-токены хранятся на сервере только в виде хеша; `POST /auth/logout` отзывает токен.
- При 401 клиент вызывает `/auth/refresh` и повторяет запрос; если refresh тоже вернул 401 — экран входа.

## Аналитика

- Период — один календарный месяц (`month=YYYY-MM`), сравнение с предыдущим календарным месяцем.
- Учитываются только `amount < 0`; `changePercent = null`, если в прошлом месяце расходов не было.

## Деньги

- В JSON суммы передаются строкой с двумя знаками после точки (`"-849.90"`), чтобы клиент не терял точность на float/double.
- На сервере и в БД — десятичный тип (`NUMERIC(14,2)` / `BigDecimal`).

## Импорт CSV

- `operation_id` — UUID (как в ARCHITECTURE.md).
- Дубликат по `(user_id, operation_id)` не обновляет существующую операцию.
- Ограничения: файл до 1 МБ, до 5000 строк данных.

## Скидки

- Каталог загружается сервером из `fixtures/offers/offers.json` (формат — `docs/data/offers-contract.md`) с upsert по `sourceId`; клиентского эндпоинта загрузки нет.
- `potentialSaving` считается только при известных обеих ценах и `salePrice < regularPrice`.

## Отложено

- `POST /sync/push`, `GET /sync/pull` — после дедлайна; в MVP online-обновление + кэш Room.
- Удаление целей — нет в плане MVP.

## Дополнительно к плану

- `GET /categories` — справочник для выбора категории в Android.

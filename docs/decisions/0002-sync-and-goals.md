# 0002. Синхронизация и типы целей в MVP

Дата: 31.10.2026. Дополняет `0001-api-contract.md`.

## Минимальный sync (отклонение от ТЗ, раздел 9)

- В MVP реализуется только `POST /sync/push` для целей и ручных смен категории операций. Идемпотентность — по `client_change_id` (UUID клиента), уникальному в рамках пользователя (`sync_changes`).
- `GET /sync/pull` и cursor отложены: таблица `sync_changes` уже содержит `id` (будущий cursor) и `version`, поэтому pull добавляется без миграции.
- Офлайн в демо — чтение Room-кэша; изменения, сделанные офлайн, уходят через push при появлении сети. Конфликты: побеждает запись с большей серверной версией (в MVP — последний принятый push).
- Причина: критерий демо — «отключение сети → просмотр кэша»; полный двусторонний sync не успевает к сроку интеграции.

## Мягкое удаление

`goals.deleted_at` и `transactions.deleted_at` добавлены по ТЗ (раздел 3). Все выборки обязаны фильтровать `deleted_at IS NULL`. Эндпоинта удаления в MVP нет.

## Два типа целей

- `saving` — накопление. `currentAmount` вводит пользователь, прогресс = `currentAmount / targetAmount`.
- `spending_limit` — лимит расходов по категории за календарный месяц. `category` обязательна (ограничение БД `ck_goals_limit_has_category`); потрачено считает backend по транзакциям месяца (`amount < 0`, по модулю), `currentAmount` вручную не вводится.
- Лимит связывает цели, аналитику и скидки: превышение или близость к лимиту — повод для рекомендации и перехода к скидкам этой категории.
